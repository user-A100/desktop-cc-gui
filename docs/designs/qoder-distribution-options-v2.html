一个 Qoder CLI 父入口，两个明确的 Global / CN 运行时

这是对你截图里「新建会话」菜单的直接延伸：用户仍只看到一次 Qoder CLI；点进去才选 Global 或 CN。供应商设置页也只保留一个 Qoder 页面，但内部有两张不能互相覆盖的配置卡。

一级导航：一个 Qoder CLI 不新增平级 CLI，不让新建会话菜单变成两个相似条目。
二级选择：Global / CN 建会话时显式选择 distribution；选择结果进入 thread 的不可变 runtime profile。
设置镜像：一页两套配置 同一个供应商页面，分别管理 binary、登录、PAT、config home 与 history。

线程内仍要显式回执 distribution

一级 UI 可以收敛为一个 Qoder CLI，但历史列表、顶部标题和助手回执必须显示实际运行身份，防止 silent fallback。

Engine qoder Distribution cn Binary qoderclicn Profile ~/.qoder-cn

原型结论：你说的「不单独再加一个 CLI 入口」在 UI 上是对的；但代码层不能因此把 CN 当作一条普通自定义路径。它必须是 Qoder 父入口下、持久化且不可串线的 distribution profile。
